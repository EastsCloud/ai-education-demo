## 3. 服务器 API 分组

路由由 `server/local-api-server.mjs` 提供，以下是职责索引，不替代正式 OpenAPI：

| 分组 | 典型路径 | 责任 |
| --- | --- | --- |
| 健康 | `/api/health` | 服务状态 |
| 身份 | `/api/auth/*` | 注册、登录、会话、资料、密码和退出 |
| 关系 | `/api/linked-students`、`/api/student-relationship-invites/*` | 学生与可选成人关系 |
| 入学 | `/api/student-onboarding-prefills/*`、`/api/onboarding-status/*` | 基本信息和流程状态 |
| 测试 | assessment 相关路由 | 性格、初始能力、阶段测试和无提示评分 |
| 目标曲线 | `/api/initial-learning-plans`、`/api/curve-adjustments` | 静态计划和正式测试后的调整 |
| 每日练习 | daily practice 相关路由 | 唯一计划、运行、交付和总结 |
| 题目 | question delivery 相关路由 | 候选验证、公开净化、服务器评分 |
| 帮你学 | hint / guided / recall 相关路由 | 累积提示、分步引导和历史回忆 |
| 图鉴 | knowledge graph / atlas 相关路由 | 节点、覆盖、探索和错题重做 |
| 报告 | learning report / peer 相关路由 | 三角色报告和匿名参照 |
| 协作 | messages / workspace 相关路由 | 成人留言和个人页面配置 |

生产化前应从这些路由生成正式 OpenAPI 3.1 文档，并加入请求、响应、错误码、权限和幂等说明。

## 4. 数据库

主要表：

```text
user_accounts
auth_sessions
account_audit_events
student_profiles
student_access_links
student_relationship_invites
student_onboarding_prefills
assessment_sessions
student_learning_goal_drafts
student_plans
daily_practice_plans
daily_practice_runs
daily_practice_sessions
question_deliveries
behavior_events
student_messages
student_preferences
observer_workspaces
```

关键事实：

- 密码只保存派生哈希，不保存明文。
- 会话令牌在数据库中保存哈希。
- 题目交付保存私有候选，学生只收到净化后的公开对象。
- `behavior_events` 既有服务器可信事件，也有严格白名单的浏览器非评分事件。
- `student_plans` 保存静态曲线、动态曲线、测试节奏和私有支持策略。
- 日计划和日运行以学生、科目、日期形成唯一边界。

详细逻辑见 `reference/data-model.md`。

## 6. 测试结构

所有 `server/*-contract.mjs` 均为无第三方测试框架的可执行合同测试。`server/run-contract-suite.mjs` 顺序执行并汇总 96 项测试。

`server/system-journey-e2e.mjs` 使用公开 API 创建五名学生、五名家长和一名老师，随机产生不同作答行为，并保留数据库和 JSON / Markdown 报告。

## 8. 已知工程债

- 当前为单进程 Node + SQLite，不是云端多租户架构。
- API 尚未生成 OpenAPI 文档。
- 数据库迁移采用启动时建表逻辑，生产应使用版本化迁移工具。
- 前端为原生模块化 JavaScript，尚未形成完整设计系统和组件测试。
- 题型和部分服务同时存在前端可执行模块；生产版应把私有生成及验证进一步收紧到服务器部署边界。
- 自动测试覆盖业务合同，但不等于负载、安全、浏览器矩阵和真实教育效果测试。
