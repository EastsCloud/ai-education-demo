# AI Education 系统结构

本文档把产品方法论拆成可开发的系统模块。它回答一个问题：如果要把“一对一、练中学、帮你学”落成系统，底层需要哪些模块，它们之间如何协作。

## 1. 系统主闭环

```text
学生进入系统
-> 入学诊断
-> 基本生理信息
-> 心理性格测试
-> 学习性格测试
-> 选择学习科目
-> 调用测试模块
-> 初始专业能力测试
-> 多维能力图
-> 初始画像
-> 目标设定
-> 静态学习曲线
-> 每日任务
-> 练中学做题
-> 帮你学提示
-> 行为数据记录
-> 知识图鉴归纳
-> 学习报告
-> 动态调整画像、任务和曲线
```

这个闭环里有三个关键原则：

- **学生不是被动接收课程，而是被系统持续理解。**
- **题目不是孤立内容，而是用来观察学生、训练学生、反馈学生的载体。**
- **AI 不是替学生学，而是让系统能更细地理解、更准地出题、更及时地提示。**
- **每一道题都必须有完整标记，才能连接学制水平、知识图鉴、能力证据、出题逻辑和行为数据。**

---

## 2. 核心模块

### 2.0 核心技术资产

AI Education 的核心不只是页面或题库，而是几类可以长期积累的数据资产：

1. **学生画像与行为数据库**：理解每个学生是谁、怎么学、哪里卡住。
2. **题目逻辑库**：定义题目如何在边界内生成、校验、变式和拆解。
3. **知识图鉴**：把练习中的经验归纳成知识结构。
4. **题目标记体系**：让每道题知道自己属于哪个学制水平、练什么知识、对应哪个图鉴节点、能证明哪些能力、适合什么运行模式。

题目标记体系是连接层：

```text
学制 / 年级水平
+ 知识点 / 知识图鉴
+ 能力维度 / 证据模型
+ 题目逻辑库 / 变量边界
+ 运行模式 / 测试或练习
+ 行为数据 / 作答证据
```

没有完整标记的题，即使题干看起来合理，也不能进入学生端。AI 实时出题同样必须先生成并通过这些标记和校验，才能被派发。

### 2.1 学生画像模块

目标：让系统先了解学生，再开始教学。注册完成后的第一件事应该是入学诊断，而不是直接派发学习任务。

功能包括：

- 基本生理信息记录
- 初始心理性格测试
- 学习性格测试
- 综合性格测试逻辑库
- 系统支持科目选择
- 测试模块调用
- 初始专业能力测试
- 学习过程中阶段测试 / 动态测试调用
- 多维能力图生成
- 学生基础信息与学习目标记录
- 动态行为数据汇总
- 学生强弱项识别
- 学习偏好与反馈偏好识别
- 学习风险识别，例如拖延、瞎答、提示依赖、反复卡点

关键输出：

- 基本生理信息
- 综合性格特征
- 多维能力图
- 学生当前水平
- 学科强弱
- 知识点掌握状态
- 题型敏感性
- 学习风格
- 需要补弱的方向
- 下一阶段学习建议

多维能力图至少包括：

- 学科知识掌握度
- 题型理解能力
- 读题与信息提取能力
- steps 推理能力
- 计算稳定性
- 变式迁移能力
- 提示依赖程度
- 学习节奏与专注习惯
- 反馈偏好和页面刺激强度偏好

多维能力图生成后，系统再结合学生或家长设定的学习目标，生成第一条静态学习曲线，并把曲线分解成阶段计划和每日任务。

初始画像不是单一测试结果，而是一个综合对象：

```text
初始画像
= 基本生理信息
+ 心理性格测试
+ 学习性格测试
+ 专业能力测试
+ 多维能力图
+ 学习目标
```

其中，专业能力测试应在学生确认具体学科之后进行。不同学科的能力图维度可以不同，但都要能回答：学生当前处于什么位置、强弱在哪里、下一步应该怎么学。

测试模块应该是系统级可复用模块：

```text
测试模块
-> 初始测试：生成初始能力图和静态学习曲线
-> 阶段测试：校准当前水平和动态学习曲线
-> 专项测试：确认某个知识点是否真正掌握
```

也就是说，前台更适合叫“测试”，而不是“诊断”。入学诊断不是单独写死一套测试，而是第一次调用测试模块。后续学习过程中，系统也可以根据学习曲线提醒、每日任务、报告建议、学习异常、老师/家长要求，重新调用测试模块来更新动态学习曲线。

测试模块不能只输出分数。它必须输出：

- 多维能力图
- 每个维度的证据题
- 错因分布
- 提示依赖层级
- 变式迁移表现
- 当前适合的推进节奏
- 对静态 / 动态学习曲线的调整建议

第一版能力测试建议短而准：10-15 题，覆盖基础概念、标准题、读题提取、步骤拆解、变式迁移和提示反应。目标是定位能力，不是制造考试压力。

能力测试题目也必须来自题目逻辑库，而不是孤立题库。这里先讨论第一层：**题目产生逻辑**，也就是一道题如何被合法、可控、可解释地生成。至于某个学生此刻应该拿到哪一道题，是第二层“用户匹配逻辑”，后面再接入用户行为模式。

题目逻辑库包括：

- 知识点逻辑
- 每个题型的样题 / seed question
- 变量结构
- 变量变化边界，也就是保证题目有解、结果合理、不违反基本逻辑的合法范围
- 能力维度映射
- 变式生成规则
- 变式边界与步骤延展边界
- steps 分解规则
- 提示层级规则
- 评分证据规则
- 出题模式规则

更详细的题目产生逻辑见 `docs/question-generation-logic.md`。该文档把这一层定义为 bounded item model / 有边界的题型模型，借鉴 Automatic Item Generation (AIG) 的 item model 思路，但服务于 AI Education 的“练中学”和实时变式出题。

以数学为例，每一类题不只是存一批题，而是存一个“可控生成单元”：一个样题，加上变量边界、变式边界和步骤延展边界。这里的边界首先是合法性边界：不能生成无解题，不能生成违反基本数量关系的题，也不能生成结果虽然能算但不符合教学目的的题。系统可以在这些边界内无限生成同类题，例如保留原结构、换 1 个数字、换 2 个数字、换条件，或增加 1-2 个步骤。

数学内容生成还要遵守一个教学原则：即使是计算训练，也尽量表现为应用题或问题解决场景。学生从一开始就应该形成“计算是为了解决问题服务”的观念，而不是把数学理解为孤立的裸算。

这会让后续机器学习和 AI 出题更有效率：AI 不需要从零发明题目，而是在结构清楚、答案可控、能力维度明确的空间里生成题目。也就是说，题目逻辑库先定义“题目可以怎样产生”；用户行为数据库以后再决定“此刻给这个学生哪一道题”。

这两层需要分开设计：

1. **题目产生逻辑**：定义题型、样题、变量边界、变式边界、步骤延展边界、答案生成和校验规则。它首先保证题目有解、关系成立、结果合理。
2. **用户匹配逻辑**：根据学生画像、学习曲线、前一天表现和行为模式，决定从哪些题型生成题、生成多少、以什么顺序给学生。

同时还要区分前台和后台：

- **后台 / 算法层**：题目产生逻辑、变量边界、合法性校验、答案生成、steps 生成、提示生成。
- **学生前台**：只看到当前题、作答、提示、解析、练习反馈和知识图鉴归纳。
- **家长 / 老师 / 后台管理端**：可以看到更高层的规则解释和教学依据，但不应把底层生成器直接暴露给学生。

学生端题目发布必须有可拆解性门槛：给出来的题，都应该是系统能够准确拆解、校验答案、生成 steps 和分层提示的题。拆解逻辑必须可验证，每一步要能追溯到题目条件、核心关系、变量定义或上一层推导，而不是只依赖 AI 写出一段看起来合理的解析。不能可靠拆解的题，不进入学生端，只进入后台校验、人工审核或 AI 多轮验证流程。

题目生成器还要输出确定型帮助结构：同一套可验证拆解逻辑，应该能展开成两种模式：折叠式分层提示和分步引导模式。前端只是选择展示模式，不能让两个模式各自生成一套互相不一致的解析。

同一道题也可以有多种可验证解题思路，例如代数法、画图法、列表法或有逻辑的试猜。多种思路不能各自脱离题型模型自由生成，而要来自同一个已校验的题目模型、核心关系和答案规则。系统可以根据学生在不同题目中自愿查看某种思路的行为，把该思路排在后续题目的可选入口前面；这只是帮助展示顺序，不能改变题目难度、评分、路径分发、任务比例、水平判断或学习曲线。学生始终可以切换和查看全部思路。

长期三步走：

1. **题库验证**：早期用人工题库和精选题验证学习闭环。
2. **题库 + 逻辑库实时出题**：中期用知识点逻辑、变量变化和步骤变化生成可控变式。
3. **云端 AI 动态出题**：后期由 AI 根据题目产生逻辑实时生成题目，再由用户匹配逻辑决定分发给谁。

因此，题库只是早期质量控制工具，真正的系统资产是“题目逻辑库 + 用户行为数据库”。

### 2.1.1 题目逻辑库 × 用户行为模式出题引擎

这是系统的核心技术能力之一。

题目逻辑库不能只根据知识点生成题，还要接入用户行为模式。也就是说，系统出题时要同时考虑：

- 当前知识点逻辑
- 当前学习曲线阶段
- 昨天做对的题
- 昨天做错的题
- 是否需要对做对题进行抽查复现
- 是否需要重做错题
- 是否提示依赖
- 是否存在瞎答、过快作答、反复卡点、长题干耗时过高等行为模式
- 是否需要原题重做、换 1 个数字、换 2 个数字、换条件、加步骤

第一阶段应先用可解释规则引擎，不直接交给机器学习：

```text
题目逻辑库
+ 用户行为模式
+ 当前阶段目标
+ 每日学习时间
-> 下一次出题逻辑
```

例如：

- 昨天做对的题：抽一部分做复现检查；对了就是对了，后台只确认是否能稳定复现。
- 昨天做错的题：进入错题重做，先原题，再轻变式。
- 靠提示做对的题：第二天检查无提示能否完成。
- 瞎答型：减少新题，增加停顿确认和读题题。
- 提示依赖型：增加轻提示后无提示重做。
- 慢但准型：减少机械重复，增加轻变式。

未来数据足够后，机器学习可以优化比例和排序，例如正确题复查比例、错题重做比例、变式推进速度、测试提醒时机。但机器学习不应该一开始决定教育方法论；它应优化已经确定的规则框架。

综合性格测试也应采用逻辑库，而不是固定题库。这里分为两层：心理性格逻辑库负责开放性、尽责性、外向性、宜人性、情绪稳定性、自我管理等底层倾向；学习性格逻辑库负责提示依赖度、挑战耐受度、表达偏好、错误反应、自主复盘等学习场景表现。逻辑库保存维度、场景、选项类型、评分映射和置信度规则；具体题目可以根据年龄、阅读舒适度和历史行为动态生成。学科能力测试另由学科题目逻辑库负责，必须发生在选学科之后。

### 2.2 目标与学习曲线模块

目标：把学生独立确认的目标，或学生与已关联家长共同确认的目标，转化为可执行、可调整的学习路径。

学生端不应把“计划”作为独立管理页面展示。计划应该融合到学习曲线、首页今日重点和每日任务中，让学生感知自己在往前走。完整计划、阶段节点、动态调整原因和节奏配置，更适合放在家长 / 老师 / 后台视图。

功能包括：

- 目标设定，例如学段水平、托福分数、学科成绩、能力水平
- 时间设定，例如 3 个月、6 个月、一个学期
- 每日学习时间设定，例如每天 20 分钟、30 分钟、45 分钟
- 每周学习频率设定，例如每周 3 天、5 天、7 天
- 基于生日推导年龄、年级阶段和同龄统计基准
- 可选生日文化模型，例如周易/生日分析作为启发式参考
- 初始学习曲线生成
- 每日强度建议
- 阶段性测试节点安排
- 根据表现动态调整曲线

静态学习曲线的输入包括：

```text
静态学习曲线
= 初始画像
+ 学习目标
+ 总学习周期
+ 每日学习时间
+ 每周学习频率
+ 同龄 / 同年级 / 同目标统计基准
+ 可选生日文化模型
```

静态学习曲线内部用“离目标的差距”计算，用户界面用“目标达成进度”展示。系统先根据能力测试结果计算当前能力水平，再和学生选择的目标水平比较；已关联家长可以参与选择，得到初始 gap。内部 gap 的终点应趋近于 0；外部 progress 的终点应趋近于 100%。

```text
Gap to Target = Target Level - Current Ability Level
Progress toward Target = 1 - Gap to Target
```

如果学生选择的总学习周期、每日学习时间和每周频率不足以支撑目标，系统要提示调整：要么延长总周期，要么提高学习强度，而不是生成一条看起来好看但不现实的曲线。已关联家长可以参与这次选择。

系统需要同时维护静态曲线和动态曲线。静态曲线是初始预期路径，动态曲线是由阶段测试确认后的真实水平路径。动态曲线可能低于、贴近或超过静态曲线，因此前端应支持双曲线叠加展示，让用户直观看到学习是否超过原计划。

动态曲线只能由测试发起更新，不能由每日练习直接更新：

```text
Daily practice -> updates next question logic
Stage / calibration test -> updates dynamic curve
```

每日练习可以影响下一次出题逻辑，例如难度、变式层级、提示策略、错题重做顺序和每日任务微调。阶段测试 / 动态校准测试 / 专项复测才可以确认期间水平，并写入动态曲线。

测试节奏默认由系统的学科策略配置。系统可以在连续练习一小段时间后发起建议测试，例如 3 天后建议小测；学生可以跳过建议测试。但到达强制测试窗口，例如 7-10 天，必须完成阶段测试或校准测试，动态曲线才能继续可靠更新。已关联家长或老师可以在观察端调整这一默认节奏。

当动态曲线超过静态曲线时，学习曲线引擎应生成两个可选策略：

- **Keep original goal**：目标不变，预计达成时间缩短。
- **Keep study intensity**：学习强度不变，预计达到的水平提高。

这两个策略应交给学生确认；已关联家长可以共同参与，系统不自动替用户改变目标。

如果学生不主动修改，系统默认采用 **Keep study intensity**：每日学习时间和每周学习频率不变，让最终结果自然向前走。如果学生超过原计划，默认结果是预计达到的水平提高；如果学生低于原计划，默认结果是继续按原强度推进，同时用测试和报告提示是否需要主动调整。

更准确地说，动态曲线变化后，系统应该把“可变化参数”拆出来，让学生在系统建议下选择；已关联家长可以共同参与：

```text
动态曲线变化
-> 系统计算新预测
-> 给出参数调整选项
-> 学生确认（可与已关联家长共同确认）
-> 生成新的目标路径和后续测试节奏
```

可调整参数包括：

- **目标水平**：维持原目标，或把目标提高到更高水平。
- **总学习周期**：维持目标不变时，可以缩短预计完成时间；落后时可以延长总周期。
- **每日学习时间**：如果目标和周期不变，可以增加或减少每日学习强度。
- **每周学习频率**：通过增加或减少每周学习天数改变曲线斜率。
- **复习 / 新题比例**：不直接改变曲线终点，但影响下一阶段达成速度和稳定性。
- **测试间隔**：领先、落后或波动较大时，可以调整建议测试和强制测试间隔。

动态曲线低于静态曲线时，也不应该简单显示“落后”。系统应给出可选择方案：

- 目标不变：延长总学习周期。
- 目标不变：增加每日学习时间或每周频率。
- 强度不变：降低阶段目标或拆成更小阶段。
- 先稳基础：提高复习和原题重做比例，暂缓加难。

动态曲线贴近静态曲线时，默认维持原目标、原强度和原测试节奏，只根据每日练习微调出题逻辑。

生日和统计数据只作为初始估计，不作为最终判断。系统不能因为生日直接判定学生性格或能力强弱；它只能根据年龄阶段和统计基准形成初始假设，再通过测试结果和后续行为数据持续校正。

如果使用周易等生日文化模型，它的定位也是初始画像里的可选参数，而不是决定性结论。它可以帮助系统提出需要观察的假设；后续日常学习反馈用于调整出题逻辑，阶段测试 / 校准测试结果用于更新动态曲线。

关键输出：

- 初始学习曲线
- 当前预测达成情况
- 每日任务量
- 是否需要延长周期
- 是否需要提高或降低每日强度

### 2.3 每日任务模块

目标：把学习曲线落到每天要做的事情。学生端今天的必须任务只有一件事：做题。复习、补弱、变式和错题回访属于后台生成逻辑和训练过程，不拆成学生要管理的任务清单。

功能包括：

- 当日知识点选择
- 当日题型选择
- 补弱任务生成
- 复习任务生成
- 变式训练任务生成
- 阶段测试任务生成
- 当日完成状态记录
- 当天全部做题历史沉淀

关键输出：

- 今日学习清单
- 今日重点知识点
- 今日重点题型
- 今日补弱目标
- 今日完成度
- 明天出题算法的历史输入

当天所有做过的题，都会成为第二天出题算法的历史基础。这里的“所有题”包括必做题、做对题、做错题、提示后做对题、一键重做错题、同类型来几道和“再练几道”。系统不能只把错题作为历史输入；做对题也要用于抽查复现、减少重复或推进变式。

每日给题的默认比例先采用：

```text
40% 昨天错题 / 未掌握题
25% 昨天做对题的抽查复现
25% 今天计划推进的新题
10% 挑战题 / 拓展题
```

这些比例是默认参数，后续根据每个学生的表现动态调整。例如，如果学生做对题的复现率很高，可以阶段性降低抽查复现比例，把题量让给新题或挑战题；如果错题负担较重，则减少新题，先稳定基础。

比例调整不依赖人工拍脑袋。第一版采用可解释规则引擎：读取最近 3 次练习的错题率、重做成功率、做对题复现率、无提示做对率、提示层数、瞎答率、变式迁移率、主动加练、挑战题成功率和疲劳信号，计算四个题目桶比例。计算后先应用每个题目桶的上下限，再归一化到 100%，最后用每日最大变化 10 个百分点的缓动规则避免节奏突变。

如果学生昨天做对的题，在抽查复现中反复做错，原来的题仍然记录为做对，但后台要把这种模式作为画像输入参数，例如“猜测倾向”或“复现脆弱”。这个信号会影响下一次出题：增加抽查复现、原题重做和读题确认，暂时减少新题和挑战题。学生端不直接显示“乱猜”这类标签。

详细算法见 `docs/daily-question-allocation-algorithm.md`。

### 2.4 练中学引擎

目标：让学生通过先做题、再反馈、再 repeat 和变式来掌握知识点。

功能包括：

- 每个知识点先出题，而不是先讲课
- 学生先尝试作答
- 做错后触发反馈
- 同一知识点 repeat 练习
- 换数字、换条件、换步骤、换表达
- 记录学生从不会到会的过程

关键输出：

- 练习结果
- 当天全部做题历史
- 错误类型
- 变式掌握情况
- 是否能迁移
- 是否需要进入知识图鉴归纳

### 2.5 帮你学模块

目标：把每一道题拆成可前进的 steps，通过分层提示帮助学生继续思考。

功能包括：

- 题目知识点识别
- 多种可验证解题思路，例如代数法、画图法、有逻辑的试猜
- 如果题目来自学生做过的原题，先提供“历史原题和我的答案”回忆入口
- 第 1 层先找逻辑关系并翻译成学科语言；数学里优先找相等关系
- 题目 steps 自动拆解
- 折叠式分层提示
- 分步引导模式：学生按步骤逐步作答，最后导出完整解题过程
- 每次只打开一层提示
- 完整解析作为最后一层
- 记录学生打开了几层提示
- 判断学生卡在哪一步

关键输出：

- 历史原题 / 历史答案引用
- 可选解题思路
- 题目问什么、已知条件、逻辑关系 / 相等关系、学科语言表达
- 题目 steps
- 分层提示
- 分步作答记录
- 导出的完整解题过程
- 提示使用记录
- 学生卡点
- 是否接近掌握
- 是否需要补弱

### 2.6 知识图鉴模块

目标：把学生在练习中悟到的东西，转化为专业表达和个性化知识记录。

功能包括：

- 知识点专业定义
- 学生自己的理解记录
- AI 对学生理解的专业归纳
- 错题代表
- 对题代表
- 突破题代表
- 理解演化时间线
- 掌握状态
- 错误模式标签
- 知识库 / 图书馆视图：展示已学、当前、可探索和预览锁定的知识点
- 每个知识点下挂相关题型、样题和可进入练习的题
- 每个知识点下挂学生错题集，包括错因标签、重做状态和下一步动作；学生可自愿进入原题重做，在提示前查看自己的上次作答。图鉴列表不直接返回正确答案或后台答案值，正确答案只通过受控的反馈与提示过程呈现

关键输出：

- 这个学生如何理解该知识点
- 这个学生在该知识点上常犯什么错
- 这个知识点下有哪些错题需要重做或变式巩固
- 这个学生是否从基础掌握走向稳定掌握
- 这个学生是否具备迁移能力
- 学生可以主动探索哪些新知识点

知识图鉴不只做事后归纳。默认学习路径仍然是练中学，但图鉴允许学生像进图书馆一样主动查找、预习和探索新知识点。学生主动进入未学知识点、查看样题或提前练习，也应记录为行为数据，用于判断探索欲和自学倾向。

### 2.7 行为观察与模式识别模块

目标：从学生真实行为中识别学习模式，而不是只看分数。

功能包括：

- 登录时间与学习习惯分析
- 进入系统次数分析
- 单次停留时间分析
- 做题时间分析
- 连续错误分析
- 瞎答识别
- 重复题型偏好识别
- 提示依赖识别
- 特定数字 / 表达 / 条件错误识别
- 速度与准确率关系分析
- 错题与答题时间关系分析
- 正确率与答题时间关系分析
- 不同题型资源消耗分析
- 不同题型反馈效果分析
- 迁移能力分析

关键输出：

- 行为标签
- 错因归类
- 风险提醒
- 任务调整建议
- 画像更新建议

需要记录的行为数据包括：

- 学生习惯几点进入系统
- 每天 / 每周进入系统次数
- 每次停留时间
- 每道题答题时间
- 每道题是否打开提示
- 每道题打开几层提示
- 是否存在过快作答
- 是否存在连续错误
- 错题和答题时间之间的关系
- 正确率和答题时间之间的关系
- 不同类型题消耗了多少时间、提示和重复次数
- 不同类型题在反馈后的正确率变化

这些数据不是为了监控学生，而是为了让系统真正理解学生如何学习。

### 2.8 学习报告模块

目标：让学生、家长、老师都能理解学习状态和下一步行动。

详细报告框架见 `docs/report-framework.md`。报告设计参考 MAP Growth、Renaissance Star 和 i-Ready 的公开报告思路，但要结合 AI Education 自己的学习曲线、行为画像、练中学和帮你学过程数据。

功能包括：

- 学生报告
- 家长报告
- 老师报告
- 学习曲线变化
- 学习时长统计
- 整体正确率
- 同类学生水平对比
- 不同能力维度变化趋势
- 知识点掌握状态
- 行为模式解释
- 典型错题、对题、突破题展示
- 下一步建议

关键输出：

- 当前水平
- 离目标还有多远
- 进步在哪里
- 问题卡在哪里
- 下一步应该怎么学
- 简单可视化图像，例如学习时长柱图、正确率曲线、同类水平标记、能力维度趋势图

报告分为两类：

- **学生端报告**：用温和、行动导向的方式展示进度、历史测试、突破、同类水平和下一步建议。
- **家长 / 老师端行为分析报告**：展示更完整的行为模式和学习分析，例如学习习惯、停留时间、答题时间、错题类型、瞎答风险、资源消耗和反馈效果。

### 2.9 实时云端出题模块

目标：长期不依赖传统题库，而是基于逻辑库和用户行为数据库生成题目。

考虑算力、成本和质量控制，出题系统应分三步走：

1. **题库出题**：在原型期或算力有限时，先使用题库保证题目稳定、答案可控、反馈可靠。
2. **题库 + 逻辑库实时出题**：中期通过知识点逻辑、题型规则、数字变化、条件变化和步骤变化，生成个性化变式题。
3. **云端 AI 动态出题**：在算力可支撑、质量控制成熟后，基于学生状态实时生成题目、steps、提示和解析。

题库在这里不是产品终点，而是早期验证闭环和控制质量的基础设施。真正的长期目标是“逻辑库 + 用户行为数据库 + 云端 AI 生成”。

功能包括：

- 题库调用
- 知识点逻辑库
- 题型规则库
- 难度规则
- 数字和条件变化规则
- 干扰项规则
- steps 规则
- 提示规则
- 用户行为数据库调用
- 根据学生状态生成题目

关键输出：

- 当前最适合学生的题
- 用于补弱的题
- 用于变式的题
- 用于迁移的题
- 用于阶段测试的题

一对一出题不是简单随机变式，而是根据学生的掌握状态逐级推进。

例如，学生做错一道题后，系统可以按以下顺序出题：

```text
原题重复
-> 不变数字重复
-> 只变 1 个数字
-> 变 2 个数字
-> 改变题干表达
-> 增加 1 个步骤
-> 增加 2 个步骤
-> 加入干扰条件
-> 迁移到同知识点不同题型
```

推进速度取决于学生表现：

- 如果学生答对且用时稳定，可以进入下一层变式。
- 如果学生答对但用时过长，需要继续巩固。
- 如果学生打开深层提示才答对，需要保持当前难度。
- 如果学生过快作答且错误率高，需要加入步骤确认。
- 如果学生连续错，系统应降低变化幅度，回到更基础的重复。

这套出题算法的目标是慢慢推进，而不是突然跳难度。

## 4. 第一阶段应优先实现的模块

第一阶段不要同时做全系统。优先实现最小闭环：

1. 学生画像的简化版
2. 学习目标与学习曲线的简化版
3. 每日任务
4. 做题页面
5. steps 分解与分层提示
6. 知识图鉴的单知识点页面
7. 学习报告的简化版

这个闭环能证明系统不是普通刷题工具，而是一个能理解学生、安排练习、提供提示、沉淀知识、输出报告的 AI 教育系统。
