# Daily Question Allocation Algorithm / 每日给题比例调节算法

本文档定义“明天给学生出什么比例的题”。它属于后台学生匹配逻辑，不直接展示给学生。

学生端只看到：开始做题、做题反馈、简单统计、可选加练。后台负责根据行为数据调节题目组合。

每次服务器确认一道作答后，也会用同一批可信行为证据更新支持策略：提示入口、任务分段和挑战节奏。当天已经开始的题组保持稳定；更新从下一次题组生效，不会在学生做题中途突然改变规则。

---

## 1. 默认比例

第一版默认比例：

```text
40% 昨天错题 / 未掌握题
25% 昨天做对题的抽查复现
25% 今天计划推进的新题
10% 挑战题 / 拓展题
```

这个比例是起点，不是固定规则。系统每天根据最近练习表现调整，但不能一天变化过大。

---

## 2. 四个题目桶

### 2.1 Wrong / Unmastered

用于处理昨天错题、无提示仍不会的题、重复卡住的题。

推进顺序：

```text
原题重做
-> 换 1 个数字
-> 换 2 个数字
-> 加 1 个步骤
-> 加 2 个步骤
-> 进入下一知识点
```

### 2.2 Correct Reproduction Sampling

用于抽查昨天做对题是否能复现。

重要边界：

- 对了就是对了。
- 学生端不说“不稳定”。
- 后台只是抽样确认复现能力。
- 如果复现率高，这个比例应阶段性下降。

### 2.3 New Planned Questions

来自静态学习曲线和今日计划推进的知识点。

如果前面错题负担过重，新题比例下降；如果学生复现和错题处理很好，新题比例上升。

### 2.4 Challenge / Extension

用于判断学生是否可以更快推进。

挑战题不是惩罚，也不是强制加压。它只在学生当天状态足够好时增加。

### 2.5 Instructional-Grade Guardrail

题目桶决定的是比例和排序，不允许它绕过当前的教学阶段。

```text
长期目标（例如 G6）
!= 今天可以直接使用 G6 题

当前教学年级 / 当前评估路由
-> 当日可用题族范围
-> 错题、复现、新题、挑战题四个桶在这个范围内选择
```

当前 MVP 以学生确认的当前年级测试路由作为每日题目的 `instructionalGrade`。因此，即使学生的长期目标更高，系统也不会因为目标标签而把当天题目跳到高年级题族。以后当正式阶段测试确认新的计划阶段时，系统可以更新这个教学年级；每日练习本身不能偷偷改变它。

---

## 3. 输入信号

算法读取最近 36 道可信作答和与之关联的当前练习行为，必要时结合最近一次阶段测试。完整历史仍保留给错题回放、知识路径和报告，不会被这一窗口抹去。

核心输入：

| Signal | 含义 |
| --- | --- |
| `wrongRate` | 错题比例 |
| `retrySuccessRate` | 错题重做成功率 |
| `correctReproductionRate` | 做对题再次复现成功率 |
| `repeatedCorrectThenWrongRate` | 做对题再次出现错误的重复比例 |
| `hintFreeCorrectRate` | 无提示做对比例 |
| `hintDepthAverage` | 平均提示层数 |
| `fastGuessRate` | 过快提交且错误的比例 |
| `slowAccurateRate` | 做得慢但正确的比例 |
| `independentControlledVariantStabilityRate` | 无提示完成换一数 / 换两数变式的成功率，仅在至少两次证据后用于增加挑战 |
| `voluntaryPracticeCount` | 主动加练数量 |
| `challengeSuccessRate` | 挑战题完成率，仅保留为支持与报告上下文，不用于加速 |
| `independentChallengeTransferEvidenceCount` | 无提示完成 R1 反向未知或 M1 真实两步变式的次数 |
| `independentChallengeTransferSuccessRate` | 上述无提示真实变式的成功率，用于决定是否可以小幅增加挑战 |
| `fatigueSignal` | 疲劳信号，例如后半段明显变慢或错误上升 |

### 3.1 题目结构特征信号

每道已校验题目还会带一组后台特征，例如题型关系、单位处理、多步骤、运算形式，以及不记录原始数值的数字模式（如是否含 0、是否含小数、数字量级、数字位特征）。

它不改变四个题桶的比例，也不改变学生的级别或学习曲线。它只在最近证据里同时满足以下条件时，帮助同一题族、同一年级范围内选择更有针对性的合法种子题：

```text
至少 5 次出现
至少 3 次错误
该特征错误率至少比当前总体错误率高 25 个百分点
至少达到中等证据量（6 次出现）才真正进入下一日匹配
```

如果没有足够证据，系统继续观察；如果存在“原题重做”，原题永远优先，不会为了特征匹配替换它。

## 4. 计算方法

### 4.1 先从默认比例开始

```text
wrong = 0.40
correctReview = 0.25
new = 0.25
challenge = 0.10
```

### 4.1A 先看证据量，再调比例

一两道题不能代表学习方式。错题仍会进入默认的重做桶，但行为造成的额外比例变化必须按证据量缓慢放大：

```text
0 道可信作答      -> 不因行为调整默认比例
1-5 道可信作答    -> 只使用 35% 的行为调整幅度
6-17 道可信作答   -> 使用 70% 的行为调整幅度
18+ 道可信作答    -> 使用完整行为调整幅度
```

这个门槛只限制“比例变化速度”，不阻止原题重做、分层提示或正式测试。它避免系统因为一次偶然对错就误判学生。

### 4.2 根据行为信号加减

第一版用可解释规则：

```text
如果 wrongRate 高 或 retrySuccessRate 低：
  wrong +10% 到 +20%
  new -5% 到 -15%
  challenge -5%

如果 correctReproductionRate 很高：
  correctReview -5% 到 -15%
  new +5% 到 +10%
  challenge +0% 到 +5%

如果 correctReproductionRate 低：
  correctReview +5% 到 +10%
  new -5%

如果 repeatedCorrectThenWrongRate 高：
  标记后台画像信号 guessing_tendency
  correctReview +5% 到 +10%
  wrong +5%
  new -5% 到 -10%
  challenge -5%

如果 hintDepthAverage 高 或 hintFreeCorrectRate 低：
  wrong +5% 到 +10%
  challenge -5%

如果至少有 2 次无提示数字变式，且 independentControlledVariantStabilityRate 高、hintFreeCorrectRate 高：
  new +5%
  challenge +5%
  correctReview -5%

如果 fastGuessRate 高：
  wrong +5%
  correctReview +5%
  new -5%
  challenge -5%

如果 slowAccurateRate 高，且无提示正确率与整体正确率稳定：
  不把“慢”当作弱点
  correctReview -3%
  new +3%
  保持稳步推进，不因为速度较慢而额外加压

如果 fatigueSignal 高：
  challenge -5% 到 -10%
  wrong 只保留必要原题重做
  新题不增加

如果 voluntaryPracticeCount >= 3，且至少有 2 次无提示的 R1 / M1 真实变式，
并且 independentChallengeTransferSuccessRate >= 75%、整体无提示正确率足够、没有疲劳信号：
  challenge +5%
  new +5%
```

提示后的挑战题完成仍然是有价值的学习和支持证据：系统可以保留分层提示或分步入口，但不会把它当成“已经可以加难”的依据。这个边界避免把帮助后的完成误读为独立迁移能力。

### 4.3 设置上下限

避免系统走极端：

| Bucket | 最低 | 最高 |
| --- | --- | --- |
| Wrong / Unmastered | 20% | 60% |
| Correct Reproduction Sampling | 5% | 30% |
| New Planned Questions | 15% | 45% |
| Challenge / Extension | 0% | 20% |

### 4.4 归一化

加减后四个比例必须重新归一化，总和为 100%。

### 4.5 缓动规则

每天每个桶最多变化 10 个百分点，避免学生感觉节奏突然变化。

```text
tomorrowRatio = todayRatio + clamp(rawRatio - todayRatio, -0.10, +0.10)
```

### 4.6 复现信号必须来自同一练习单元

“做对后又错”不能把同一知识点下的任意两道题混在一起判断。第一版只使用同一个练习单元中已经被服务器关联的证据：

```text
原题（无提示完成）
-> 换一个数字
-> 换两个数字
```

如果后续变式最终也能无提示完成，系统把途中一次错误视为可恢复的学习过程；只有后续变式仍未独立完成，才作为需要更多复现的信号。没有这种明确关联时，系统宁可继续收集数据，也不推断学生在“乱猜”。

## 5. 示例

### 情况 A：做对题复现率很高

输入：

```text
wrongRate = 12%
correctReproductionRate = 94%
hintFreeCorrectRate = 88%
variantTransferRate = 82%
```

输出建议：

```text
30% 错题 / 未掌握题
10% 做对题抽查复现
40% 新题
20% 挑战题 / 拓展题
```

解释：学生已经能稳定复现做对题，不需要大量重复抽查，把空间给新题和挑战题。

### 情况 B：错题负担很重

输入：

```text
wrongRate = 42%
retrySuccessRate = 38%
hintDepthAverage = 2.4
```

输出建议：

```text
55% 错题 / 未掌握题
25% 做对题抽查复现
15% 新题
5% 挑战题 / 拓展题
```

解释：先稳定基础，减少新题和挑战题。

### 情况 C：学生主动加练且挑战题成功

输入：

```text
wrongRate = 16%
voluntaryPracticeCount = 8
challengeSuccessRate = 80%
fatigueSignal = low
```

输出建议：

```text
30% 错题 / 未掌握题
15% 做对题抽查复现
35% 新题
20% 挑战题 / 拓展题
```

解释：学生主动性和挑战承受能力较强，可以适当加快推进。

## 6. AI / ML 升级路径

第一阶段不用黑箱模型，先用可解释规则引擎。

第二阶段，当系统积累足够学生行为数据后，可以用机器学习优化参数：

```text
输入：行为信号 + 当前能力图 + 学习目标 + 历史题目表现
输出：四个题目桶比例 + 题目排序 + 提示策略
优化目标：阶段测试提升、知识点完成度、复现率、低挫败感、高持续学习率
```

机器学习只能优化比例和排序，不能绕过题型模型的合法性边界，也不能直接更新动态学习曲线。动态曲线仍然只能由阶段测试或校准测试更新。

---

## 7. 画像回流

如果学生昨天做对的题，在抽查复现中反复做错，这不是把原来那次“做对”改成“做错”。原来的结果仍然是做对。

但多次出现这种模式时，后台要把它作为学生画像输入参数：

```text
profileSignal = guessing_tendency / reproduction_fragility
```

这个信号会影响：

- 增加做对题抽查复现比例。
- 增加原题重做和轻变式。
- 增加读题确认或步骤确认。
- 暂时降低新题和挑战题比例。
- 在家长 / 老师端显示为“需要关注复现能力”，而不是给学生贴负面标签。

每一次做对题抽查复现都必须在后台绑定到一条具体的无提示正确历史记录。学生拿到的是同一数学关系的新情境题，浏览器不会收到该历史题的来源编号、种子或答案。只有这种已绑定的新情境结果可以进入复现信号，不能用“同题型的任意一次做错”替代。

---

## 8. 产品边界

- 学生端不展示后台比例。
- 学生端不说“你不稳定”。
- 学生端不直接说“你在乱猜”。
- 做对题仍然记录为做对。
- 抽查复现是后台学习策略，不是否定学生结果。
- 比例变化要渐进，不能突然让学生感觉今天难度失控。
- 更高的长期目标不能绕过当前教学年级；所有当日题族必须先通过教学年级筛选。
