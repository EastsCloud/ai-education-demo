# AI Education 角色与信息权限

本文档用于定义不同角色能看到什么、能做什么，以及哪些信息只用于系统内部判断。

## 1. 学生端定位

学生端不是“画像展示页”，而是学生自己的学习空间。

学生应该看到的是：

- 我现在学到哪里了
- 我今天要做什么
- 我可以怎么练
- 我哪里进步了
- 我下一步要做什么
- 老师或家长有什么留言
- 我在同类学生中的大致水平

学生不应该直接看到的是：

- 系统对他的完整心理 / 性格画像
- 过于标签化的行为判断
- 可能造成自我暗示的负面分类
- 老师和家长之间的内部沟通
- 系统算法层面的原始判断

核心原则：

**给学生反馈和方向，不给学生贴标签。**

---

## 2. 学生能看到什么

### 2.1 学习进度

学生可以看到自己的学习进度。

包括：

- 当前目标
- 当前所处阶段
- 学习曲线
- 当前掌握度
- 每日任务完成情况
- 阶段目标达成情况
- 与目标之间的距离

进度展示要让学生知道“我正在往前走”，而不是只看到分数。

### 2.2 做题与练习

学生可以进入做题和练习。

包括：

- 今日任务中的题目
- 错题回访
- repeat 练习
- 变式训练
- 阶段小练习
- steps 分解
- 折叠式分层提示
- 提交答案与反馈
- 重做

做题页是“练中学”和“帮你学”的核心入口。

### 2.3 测试

学生可以参加测试。

测试类型包括：

- 初始学科测试
- 阶段性测试
- 单知识点小测
- 目标进度测试
- 复习后测试

学生看到的测试结果应该偏行动导向：

- 哪些地方掌握得不错
- 哪些地方还需要练
- 下一步建议做什么
- 学习曲线是否有调整

不建议把测试结果做成单纯排名压力。

### 2.4 测试历史结果

学生可以查看自己的历史测试结果。

包括：

- 测试日期
- 测试主题
- 得分或掌握度
- 关键进步
- 主要问题
- 当时系统给出的下一步建议
- 与当前水平的变化对比

历史结果的目的不是让学生反复看过去的失败，而是看到自己如何变化。

### 2.5 页面风格选择

学生可以选择自己的页面风格。

包括：

- 简洁模式
- 活泼模式
- 专注模式
- 深色 / 浅色模式
- 字体大小
- 信息密度

这个功能的意义不只是美化，而是体现“一对一”：不同学生适合不同界面刺激强度和信息密度。

### 2.6 头像上传

学生可以上传或更换自己的头像。

包括：

- 上传头像
- 选择默认头像
- 修改昵称
- 个性化学习空间

头像和风格选择一起，让学生觉得这是自己的学习空间。

### 2.7 知识图鉴

学生可以查看知识图鉴。

学生端的知识图鉴应该展示：

- 知识点专业表达
- 自己的理解记录
- AI 对自己理解的归纳
- 错题代表
- 对题代表
- 突破题代表
- 理解演化时间线
- 当前掌握状态

知识图鉴对学生的意义是：看见自己如何从不会到会，而不是看一份普通百科。

### 2.8 家长或老师留言

学生可以看到家长或老师给他的留言。

留言类型包括：

- 鼓励
- 提醒
- 学习建议
- 任务说明
- 阶段反馈
- 老师布置的重点

留言需要和学习任务适度关联。例如：

- 某条留言关联到今日任务
- 某条留言关联到阶段测试
- 某条留言关联到知识图鉴中的某个突破

学生不需要看到老师和家长之间的全部沟通，只看到明确给自己的留言。

### 2.9 同类学生中的水平

学生可以看到自己在同类学生中的大致水平。

这里的“同类学生”需要定义清楚，例如：

- 同年龄段
- 同年级
- 同学习目标
- 同起点水平
- 同学习时长
- 同知识点进度

展示方式应避免制造过强排名压力。

推荐表达：

- 你目前处在同目标学生的前 40%
- 你在“列方程”上的速度高于同类平均
- 你在“题意分析”上仍低于同类平均，需要继续练
- 你的提示依赖已经低于同类平均

不推荐表达：

- 你排第几名
- 你落后多少人
- 你比谁差

学生端同类水平的目标是帮助学生定位自己，而不是制造焦虑。

## 3. 学生端页面建议

学生端功能很多，但页面必须保持简单。原则是：

**少页面，多融合；功能藏在自然位置里，不把学生端做成复杂后台。**

建议学生端只保留 4 个主页面：

1. 首页
2. 测试
3. 练习
4. 进度报告

再保留一个右上角个人入口：

- 头像
- 页面风格
- 昵称
- 专注 / 简洁 / 活泼模式
- 字体大小和信息密度

其中：

- 首页整合今日任务、学习曲线、留言提醒、最近进步、学习状态
- 测试承接初始测试、阶段测试、专项复测和测试历史入口
- 练习整合做题、今日任务执行、分层提示、求助和收藏
- 知识图鉴作为练习、解析、报告后的二级入口，不作为主导航
- 进度报告整合历史测试、同类水平、成就、复习提醒、下一步建议

这样，学生端虽然具备很多能力，但只需要理解 5 个主要入口。

### 3.1 功能融合方式

| 功能 | 融合到哪里 | 说明 |
| --- | --- | --- |
| 学习进度 | 首页 + 进度报告 | 首页看当前，报告看历史 |
| 做题练习 | 练习 | 练习页是核心学习场景 |
| 测试 | 测试 + 进度报告 | 初始测试、阶段测试和专项复测从测试模块进入，历史结果放报告 |
| 测试历史 | 进度报告 | 不单独做页面 |
| 页面风格 | 右上角个人入口 | 不占主导航 |
| 上传头像 | 右上角个人入口 | 和个人空间放一起 |
| 知识图鉴 | 练习 + 解析 + 进度报告 | 二级入口，不作为学生端主导航 |
| 老师 / 家长留言 | 首页提醒 + 进度报告 | 重要留言在首页露出，完整记录在报告 |
| 同类学生水平 | 进度报告 | 用温和参照，不做硬排名 |
| 目标管理 | 首页学习曲线 + 每日任务 | 目标不单独开页面 |
| 复习提醒 | 每日任务 + 进度报告 | 今天要复习什么直接进入任务 |
| 错题与突破 | 知识图鉴 + 进度报告 | 图鉴看知识点，报告看阶段变化 |
| 成就鼓励 | 首页 + 进度报告 | 首页轻提示，报告详细看 |
| 学习节奏设置 | 练习 | 今天轻一点 / 挑战一点，放在练习页 |
| 求助入口 | 练习 | 卡题时向 AI / 老师求助 |
| 收藏与笔记 | 练习 + 知识图鉴 | 题目收藏进图鉴 |
| 学习回放 | 知识图鉴二级入口 | 看一个知识点从不会到会 |
| 情绪 / 状态反馈 | 首页 + 练习 | 今天状态会影响练习强度 |

## 4. 学生端信息分级

### 4.1 可以直接展示

- 学习进度
- 每日任务
- 练习题目
- 测试结果
- 历史测试
- 知识图鉴
- 老师 / 家长给学生的留言
- 同类学生中的大致水平
- 页面风格与头像设置

### 4.2 可以转化后展示

这些信息系统可以知道，但需要转成温和、行动导向的表达再给学生看：

- 行为模式
- 错误类型
- 提示依赖
- 学习风格
- 拖延倾向
- 与同类学生的比较
- 登录和学习习惯
- 答题时间变化
- 正确率与时间关系
- 不同题型的资源消耗

例如：

- 不直接说“你有提示依赖”
- 可以说“今天先尝试 2 分钟，再打开提示”
- 不直接说“你有瞎答倾向”
- 可以说“这类题今天先写出第一步，再提交答案”

### 4.3 不直接展示

- 完整学生画像
- 性格测试细分标签
- 负面行为标签
- 系统内部算法判断
- 老师 / 家长内部备注
- 可能造成心理压力的硬排名

---

## 5. 对当前原型的影响

当前学生端原型需要继续调整：

- 左侧导航需要加入“测试”
- 左侧导航可以加入“留言”或在首页显示留言入口
- 页面风格和头像可以放入“我的设置”
- 进度报告里要加入历史测试结果和同类水平
- 首页保留学习曲线和今日任务入口
- 学生端仍不显示“画像”页面

## 6. 家长 / 老师观察端定位

家长和老师在这个系统中的边界可以基本一致。

原因是：AI Education 的终极教育目标不是让家长或老师替学生学，而是帮助学生形成 **一对一 + AI 辅助下的自学能力**。家长和老师的主要角色都是观察、理解、支持和必要时介入。

因此，家长端和老师端可以共享一套核心观察能力：

- 看学生当前进度
- 看学习曲线
- 看每日任务完成情况
- 看测试结果和历史变化
- 看知识点掌握情况
- 看错题、对题、突破题
- 看行为模式归纳
- 看系统建议
- 给学生留言
- 调整或确认学习目标
- 查看同类学生参照
- 判断是否需要人工介入

差别不在于“能不能看”，而在于默认页面重点和使用场景不同。

### 6.1 家长默认关注

家长通常更关心：

- 孩子有没有在学
- 是否按计划推进
- 离目标还有多远
- 最近是否有进步
- 哪些地方需要鼓励
- 是否需要调整学习强度
- 老师或系统建议家长怎么配合

家长端语言应该更解释性、更少技术术语。

### 6.2 老师默认关注

老师通常更关心：

- 学生具体卡在哪些知识点
- 哪些题型需要补弱
- 错误模式是什么
- 提示依赖是否下降
- 变式迁移是否形成
- 是否需要人工讲解
- 是否有共性问题可用于教学调整

老师端可以保留更多专业术语和细分数据。

### 6.3 共同原则

家长和老师都不应该把系统报告当成简单评价工具。

家长 / 老师端的核心目的不是评判学生，而是帮助学生更好地自学。

### 6.4 观察端诊断输出

家长 / 老师端除了看到心理性格测试、学习性格测试和专业能力测试的多维度图之外，还必须看到系统给出的行动建议。

核心输出包括：

- **重点关注**：告诉家长 / 老师当前最需要关注什么，例如长题干、连续错误、提示依赖、情绪恢复、任务拖延。
- **适配学科**：根据学生的心理性格、学习能力和当前表现，建议哪些学科或学科模块更适合当前阶段推进。
- **学科推进节奏**：对已选学科给出推进方式，例如先原题重做，再换数字，再加步骤，每几周进行阶段测试。
- **介入建议**：说明家长或老师应该如何配合，例如鼓励复盘、减少催促、提供结构化讲解、暂缓加难度。

观察端不应该只给数据图，而要把图转化成“下一步怎么做”。

## 7. 家长 / 老师页面自定义

家长和老师可以在自己的页面中，通过下拉菜单定制自己想看的内容。

这意味着系统不需要为每个角色固定死一个页面，而是提供一组可选择的信息模块。

### 7.1 可配置模块

下拉菜单可以让家长或老师选择显示哪些模块：

- 学习曲线
- 今日任务完成情况
- 阶段测试结果
- 历史测试趋势
- 知识点掌握地图
- 错题代表
- 对题代表
- 突破题代表
- 提示使用情况
- 行为模式归纳
- 同类学生参照
- 系统下一步建议
- 给学生的留言
- 学习强度建议
- 目标调整建议
- 阶段测试 interval 配置

### 7.2 推荐视图模板

系统可以提供几个默认模板：

- **家长简洁视图**：进度、任务完成、进步、下一步建议、留言。
- **家长详细视图**：增加测试历史、知识点掌握、同类参照。
- **老师诊断视图**：知识点、错因、提示使用、变式迁移、人工介入建议。
- **老师班级视图**：多个学生的共性问题和重点学生提醒。
- **目标追踪视图**：学习曲线、阶段测试、目标达成预测。

用户可以从下拉菜单切换这些视图，也可以进一步勾选模块。

### 7.3 自定义的意义

自定义页面有三个价值：

- 不同家长和老师关心的信息不同。
- 同一个人在不同阶段关心的信息也不同。
- 系统可以保持统一数据底座，但前端展示可以高度个性化。

这也符合“一对一”的思想：不仅学生学习是个性化的，观察者看到的信息也应该是可定制的。

## 8. 家长 / 老师与学生的信息边界

家长和老师能看到比学生更完整的分析，但仍然需要注意表达方式。

### 8.1 可以给家长 / 老师直接看

- 学习曲线
- 任务完成情况
- 测试结果
- 历史测试趋势
- 知识点掌握状态
- 错误类型
- 提示使用情况
- 行为模式归纳
- 同类学生参照
- 系统建议
- 是否需要人工介入
- 进入系统时间习惯
- 进入系统次数
- 单次停留时间
- 答题时间分布
- 错题与答题时间关系
- 正确率与答题时间关系
- 是否存在过快作答或瞎答风险
- 不同题型的时间、提示、重复次数消耗
- 不同题型在反馈后的改善效果

### 8.2 需要谨慎表达

- 性格测试结果
- 负面行为标签
- 拖延、瞎答、逃避难题等判断
- 同类学生比较
- 学习强度不足

这些信息可以给家长 / 老师看，但要用支持性语言表达。

例如：

- 不写“学生瞎答严重”
- 可以写“最近存在快速作答但正确率低的情况，建议增加步骤确认”

### 8.4 家长 / 老师行为分析报告

家长和老师端可以看到比学生端更完整的行为模式和学习分析报告。

报告可以包括：

- 学生通常几点进入系统
- 每天 / 每周进入系统次数
- 每次停留时间
- 学习持续性变化
- 不同题型平均答题时间
- 错题和答题时间的关系
- 正确率和答题时间的关系
- 是否存在过快作答但错误率高的情况
- 是否存在停留时间长但有效练习少的情况
- 哪些题型消耗了最多时间和提示
- 哪些题型在反馈后改善最快
- 哪些题型反复消耗资源但效果不明显

这些报告的目的不是监督学生，而是帮助家长和老师判断：

- 学生是否真的在学习
- 学生卡在哪里
- 学生需要鼓励、提醒还是人工介入
- 当前任务强度是否合适
- 系统下一步出题和补弱是否合理

### 8.5 家长 / 老师端看到的出题逻辑

家长和老师可以看到系统为什么给学生出这些题。

例如：

```text
昨天该学生在“总数 + 差值”题型中连续错误。
系统今天没有直接增加难度，而是先重复原结构题。
学生完成后，系统将逐步变 1 个数字、变 2 个数字，再增加一步条件。
```

这种解释可以让家长和老师理解：系统不是让学生机械刷题，而是在根据学生表现做一对一推进。

### 8.3 不应共享给学生

家长 / 老师端看到的内部分析，不一定都要同步给学生。

学生端只需要看到：

- 我下一步怎么做
- 我哪里有进步
- 我怎样能做得更好

而不是看到所有诊断标签。

## 9. 对后续原型的影响

后续原型需要新增一个“观察端”结构，而不是分别做完全不同的家长端和老师端。

建议结构：

1. 学生端：学习空间
2. 观察端：家长 / 老师共用
3. 系统后台：算法、画像、数据配置

观察端需要支持：

- 角色切换：家长 / 老师
- 视图模板下拉菜单
- 模块自定义
- 给学生留言
- 查看学生报告
- 查看系统建议

这样可以避免过早把家长和老师拆成两套系统，同时保留足够的个性化配置空间。
