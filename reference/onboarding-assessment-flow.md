# AI Education 入学诊断与静态曲线生成

本文档专门定义学生注册完成后的第一段流程。它是一对一系统的前提，必须发生在每日任务和练习之前。

---

## 1. 核心顺序

真实产品流程应该是：

```text
学生注册
-> 基本信息收集
-> 心理性格测试
-> 学习性格测试
-> 从系统支持的科目中选择学习科目
-> 进入测试模块
-> 完成该科目的初始专业能力测试
-> 生成多维能力图
-> 形成初始画像
-> 确定学习目标
-> 确定每日学习时间、每周频率和总学习周期
-> 生成静态学习曲线
-> 分解阶段计划
-> 派发每日任务
-> 进入练习
```

当前练习页里的“原题 -> 换 1 个数字 -> 换 2 个数字”规则先保留为后续训练阶段规则，不继续扩展。现在优先补齐前面的入学诊断流程。

---

## 2. 第一步：基本信息收集

基本信息不是为了给学生贴标签，而是为了给系统提供初始约束。

默认由学生自己填写这些信息。真实使用中，家长或老师也可能先在自己的板块里创建学生档案，录入生日、年级、课程体系、作息、设备等标准化信息；这只是可选预填。学生进入系统后，这些值自动带入学生端，由学生确认或轻量调整。无论是否有成人关联，学生都能独立继续。

需要收集：

- 生日
- 年龄
- 年级
- 当前学期或假期阶段
- 作息习惯
- 每次可专注的大致时长
- 阅读舒适度
- 使用设备

生日的作用：

- 推导年龄和年级阶段
- 匹配同年龄 / 同年级统计基准
- 如用户允许，可接入可选生日文化模型作为启发式参数

边界：

生日、统计基准、生日文化模型都只能作为初始假设，不能直接决定学生能力或性格。后续必须由测试结果和学习行为校正。

---

## 3. 第二步：综合性格测试

综合性格测试应该分成两层：先做心理性格测试，再做学习性格测试。当前页面已有的场景题更接近第二层，它可以保留，但不能替代第一层，也不能替代后面的学科能力测试。

### 3.1 心理性格测试

心理性格测试的作用是了解学生比较稳定的底层倾向，例如如何面对新事物、如何管理自己、如何与人互动、如何处理挫折。它不做医学诊断，也不把学生定型。

专业上可以参考三类框架：

- Big Five / OCEAN：开放性、尽责性、外向性、宜人性、情绪稳定性。
- OECD 社会情绪能力：任务表现、情绪调节、协作、开放心态、与他人互动等。
- CASEL SEL：自我认知、自我管理、社会认知、人际关系、负责任决策。

第一版心理性格维度：

Page 03 已确定采用更适合产品落地的 **心理性格测试 v1：学习支持测评**。它参考 Big Five / OCEAN、OECD social and emotional skills、CASEL SEL，但不把专业框架直接暴露给学生，而是收敛成 5 个系统可行动维度：

| 产品维度 | 系统要判断什么 | 影响什么 |
| --- | --- | --- |
| 探索与好奇 | 面对新内容是否愿意试、愿意问为什么，还是更需要稳定结构 | 变式挑战、知识图鉴延展、探索题开放频率 |
| 自我管理 | 能否自己启动任务、持续推进，还是需要切小任务和提醒 | 每日任务切分、提醒频率、开始页设计 |
| 挫折恢复 | 做错或结果不理想后，适合直接复盘、降压恢复还是陪伴分析 | 错题反馈强度、恢复题、难度推进速度 |
| 互动与求助 | 更适合独立想一会儿，还是需要老师 / 家长 / AI 及时回应 | 提示出现时机、老师 / 家长留言方式、独立思考窗口 |
| 接受反馈方式 | 更适合直接指出问题、轻提示、鼓励后纠正，还是一步步带着做 | AI 反馈语气、默认提示层级、分步引导入口 |

题量逻辑：

- 心理性格测试和下一步学习性格测试合计不超过 12 题。
- 建议分配：心理性格约 6 题，学习性格约 6 题。
- 每个维度在入学阶段只需要获得初始信号，不强求一次测准。
- 如果某个维度信号矛盾或置信度不够，不在入学阶段继续加题，而是标记为低置信度，后续通过真实学习行为和轻量小问题继续校正。
- 学生端不显示精确题号和总题数，只显示模糊进度。

这里的关键不是用 12 题一次性测准学生，而是用 12 题生成第一版支持策略。真正的一对一画像来自后续持续行为观察。系统应该把答题时间、提示层级、无提示重做、错题重做选择、同类型加练、是否挑战更难变式、是否打开知识图鉴、是否查看错题详情、进入系统时间和停留时间等行为，都作为画像校正信号。这样画像会随着真实学习越来越准，而不是停留在入学问卷。

心理性格测试应该更多使用生活和校园场景题，例如“任务快截止时怎么开始”“测试失利后怎么反应”“遇到不会的问题是否求助”。题目可以由逻辑库动态生成，但维度和评分映射要稳定。

### 3.2 学习性格测试

学习性格测试是性格测试的第二层，直接面向学习场景。它不判断数学、英语等学科知识水平，只帮助系统判断学生更适合怎样练、怎样接收提示、怎样面对错误、怎样推进挑战。

第一版学习性格维度建议收敛为 5 个产品可行动维度：

| 维度 | 系统要判断什么 | 影响什么 |
| --- | --- | --- |
| 提示依赖度 | 遇到困难时，是想自己再试、轻提示、分步引导，还是直接看解析 | 默认提示层级、提示出现时机、是否限制过早看答案 |
| 挑战耐受度 | 更适合稳定重复、轻微变化、逐步加难，还是主动挑战 | 变式推进速度、难题开放时机、恢复题比例 |
| 表达偏好 | 更容易接受文字、图示、步骤、例题哪种呈现 | 题目说明、提示形式、知识图鉴表达方式 |
| 错误反应 | 做错后是愿意重做、看原题答案、做同类型，还是容易跳过 | 错题反馈策略、重做入口、同类题推荐 |
| 自主复盘倾向 | 是否愿意看知识图鉴、错题记录、今日总结 | 归纳内容露出程度、复盘提醒方式、报告简化程度 |

输出：

- 学习性格摘要
- 适合的反馈方式
- 适合的任务节奏
- 初始提示策略
- 需要观察的风险点
- 推荐内容呈现方式，例如文字型、图形型、步骤型、互动型
- 学生端轻松分类，例如探索型起步者、结构提示型学习者、稳步推进型
- 同类学生占比，例如“约占同龄同目标学生 18%”
- 面向学生的推荐练法，例如轻提示、短任务、图示辅助、变式挑战

边界：

这些维度不是为了给学生贴“外向/内向”“纪律性差”等标签，而是为了形成系统的初始教学策略。后续仍然要通过真实学习行为动态校正。

Page 04 交互建议：

- 一题一屏，不做成一次性长问卷。
- 学生端不显示第几题或总题数，只显示模糊进度。
- 每题 4 个大按钮，学生点选后才能继续。
- 完成后不给分数，只给一句轻结果，例如“系统会先让你自己试，再打开轻提示”。
- 完成后进入选择学科，随后才进入初始学科能力测试。

Page 04 MVP 六个轻场景：

| 序号 | 场景 | 维度 |
| --- | --- | --- |
| 1 | 一道题卡住了，希望系统先怎么帮 | 提示依赖度 |
| 2 | 连续错了两次，下一步想怎么做 | 错误反应 |
| 3 | 刚做对一类题，下一步怎么加变化 | 挑战耐受度 |
| 4 | 更容易看懂哪种帮助 | 表达偏好 |
| 5 | 今天练完后更愿意看什么 | 自主复盘倾向 |
| 6 | 觉得自己会但又错了，会怎么做 | 错误反应二次验证 |

### 3.3 学生端轻松反馈

学生端测试结果不能只显示题目和分数，也应该用轻松方式帮助学生认识自己的学习特点。这个部分可以显示“学习类型卡”和“同类人群比例”。

学生端表达方式：

- 用正向、中性、有趣的名称，不使用“缺陷型”“低自律”“高焦虑”等标签。
- 可以告诉学生：“你更接近探索型起步者，约占同龄同目标学生 18%。”
- 可以推荐练法：“你适合先自己试，再打开一层轻提示。”
- 可以显示人群属性：“这一类学生通常在变式题里进步快，但遇到长题干时需要分段。”
- 不显示后台完整维度分数和风险标签。

学生端分类不是永久身份，而是当前阶段的学习状态。后续系统会根据真实练习行为调整分类和推荐。

### 3.4 家长 / 老师端观察反馈

家长和老师端可以看到更完整的多维度图，但不能只停留在图表展示。系统需要把测试结果转化为可执行建议。

观察端输出：

- 心理性格测试多维度图
- 学习性格多维度图
- 专业能力测试多维度图
- 当前重点关注，例如长题干、连续错误、提示依赖、情绪恢复、任务拖延
- 适配学科或适配模块，例如数学应用题、英语阅读、科学实验推理
- 当前学科推进节奏，例如原题重做、换 1 个数字、换 2 个数字、增加步骤、阶段测试
- 家长 / 老师介入建议，例如鼓励复盘、提供结构化讲解、暂缓加难度、减少直接给答案

观察端的目标是让家长和老师知道“现在应该怎么帮”，而不是只知道“学生是什么样”。

### 综合性格测试逻辑库

综合性格测试不应该长期依赖固定题库，而应该有两个“测试逻辑库”：心理性格逻辑库和学习性格逻辑库。逻辑库固定的是维度、场景、选项映射和评分规则，具体题目可以由系统动态生成。学科能力测试另有学科题目逻辑库，必须发生在选学科之后。

逻辑库包括：

- 测试维度，例如开放性、尽责性、外向性、情绪稳定性、好奇心、探索欲、独立性、耐受力、纪律性、图文偏好。
- 心理场景，例如面对新事物、长期任务、同伴互动、测试失利、求助选择。
- 学习场景，例如做错题、遇到难题、选择提示、复盘、探索变式、完成每日任务。
- 选项类型，例如直接看答案、要一层提示、自己再试、换一道更简单的题、挑战更难变式。
- 评分映射，例如某个选项提高“独立性”分，也可能降低“提示依赖风险”。
- 置信度规则，例如同一维度至少通过 2-3 个不同场景交叉验证。
- 动态生成规则，例如根据学生年龄、科目、阅读舒适度和历史行为生成更贴近学生的题面。

这样做的好处：

- 题目不是固定的，可以随年龄、科目和学习阶段变化。
- 同一个维度可以通过多个不同场景反复观察。
- 后续学习过程中也可以继续用小问题校正画像，而不是只在注册时测一次。
- 测试结果更容易回流到系统动作，例如提示方式、任务节奏、难度推进。

示例：

```text
维度：独立性
场景：连续两次做错
动态题面：你做一道数学题连续错了两次，这时你更希望系统怎么做？
选项 A：先别告诉我答案，让我再试一次
选项 B：给我一个很轻的提示
选项 C：一步一步带我做
选项 D：直接给我完整解析
评分：A 提高独立性和探索欲，B 提高中等独立性，C 提高步骤依赖，D 提高答案依赖风险
```

### 综合性格测试的出题边界

这一部分应该定位为“学习支持测评”，不是心理诊断，也不是人格定型。出题时遵守以下边界：

1. **只问学习情境，不问泛人格判断**
   - 推荐：当一道题连续做错两次，你更希望系统怎么帮助你？
   - 避免：你是不是一个没有耐心的人？

2. **只形成初始假设，不形成永久标签**
   - 测试结果只能用于生成初始教学策略。
   - 后续必须由真实行为数据校正，例如答题时间、提示使用、重做次数、变式迁移结果。

3. **每个题目必须能对应系统动作**
   - 好奇心 -> 是否给探索题、知识图鉴入口。
   - 耐受力 -> 难度推进速度、鼓励频率。
   - 纪律性 -> 任务提醒、检查机制。
   - 独立性 -> 提示出现时机、老师/家长介入频率。
   - 文字 / 图形偏好 -> 内容呈现方式，但不能限制学习方式。

4. **避免价值评判**
   - 不使用“好/坏”“强/弱人格”“自律差”等表达。
   - 使用中性表达，例如“当前更适合短任务反馈”“当前需要更清晰的步骤框架”。

5. **谨慎使用学习风格**
   - 可以记录学生的文字、图形、步骤、互动偏好。
   - 不能假设“学生只适合某一种方式学习”。
   - 系统应提供多模态呈现，并根据真实表现判断哪种方式有效。

6. **避免高风险心理问题判断**
   - 不做焦虑症、抑郁、注意力障碍等诊断。
   - 如发现持续异常行为，只能提示家长或老师“需要进一步关注”，不能给医学或心理结论。

7. **题目应采用场景选择题**
   - 用具体学习情境让学生选择反应。
   - 少用抽象自评，例如“我很自律”“我很外向”。
   - 每个维度至少用 2-3 个不同场景交叉验证，避免单题定性。

8. **结果对学生端要温和**
   - 学生端看到的是建议和适配方式。
   - 家长 / 老师端可以看到更完整的倾向分析。
   - 系统后台保留原始维度分数和置信度。

---

## 4. 第三步：确认学习学科

专业能力测试必须在学生确认学科之后进行。系统应该先展示当前支持的科目，学生选择一个科目后，再进入该科目的测试模块；已关联家长可以提供建议，但不构成前置条件。

原因：

- 不同学科的能力维度不同。
- 数学重 steps、题型、计算、迁移。
- 英语重词汇、语法、阅读、听力、表达。
- 托福重分项能力、目标分数、时间约束。

MVP 第一阶段先确认：

```text
学科：数学
目标知识簇：一次方程应用题
```

系统支持科目的数据结构应包含：

- 科目名称
- 当前是否开放
- 可测试的知识簇
- 对应测试模块
- 可生成的能力图维度

---

## 5. 第四步：测试模块与专业能力测试

测试模块是一个可复用模块，不只用于入学诊断。它有两个用途：

1. **初始测试**：学生第一次选择学科后，用来了解该学科当前起点，并生成初始多维能力图。
2. **阶段测试 / 动态测试**：学习过程中定期或按需调用，用来校准学习曲线，生成动态学习曲线调整依据。

因此，测试模块应独立于“入学诊断页面”。入学诊断只是第一次调用它；后续每日任务、阶段计划、老师/家长要求、系统判断需要校准时，也可以再次调用。

测试模块输出：

- 测试结果
- 多维能力图
- 当前强项和弱项
- 错因分布
- 提示依赖情况
- 变式迁移情况
- 对静态学习曲线或动态学习曲线的调整建议

专业能力测试用于了解学生当前在该学科里的真实起点。

它不是传统意义上的考试，而是一次“能力定位”。测试题必须服务于三个目标：

- 找到当前起点：学生已经会什么、哪些能力稳定。
- 找到关键卡点：在哪个步骤、题型、表达方式或条件变化中出错。
- 生成后续路径：静态学习曲线、第一阶段每日任务、练习推进节奏都要来自测试结果。

做题运行层应该共用同一个底层模块，但有不同模式：

```text
Question Runtime
-> Assessment Mode
-> Practice Mode
```

Assessment Mode 用于初始学科能力测试、阶段测试和专项复测：

- 不开放帮你学分层提示。
- 不现场给完整解析，避免测试变成教学。
- 可以允许学生选择“不确定 / 跳过”，作为能力定位信号。
- 记录答案、用时、题型、能力维度、卡点、修改行为和不确定信号。
- 结果进入多维能力图、静态曲线或阶段动态曲线。

Practice Mode 用于每日练习：

- 开放帮你学：轻提示、分层提示、分步引导、原题回忆。
- 错题进入原题重做、换 1 个数字、换 2 个数字、增加步骤。
- 记录提示层级、重做、变式迁移和加练行为。
- 影响下一次出题逻辑，但不直接更新动态曲线。

能力测试题目应该分层：

1. **基础概念题**：判断是否理解最小知识单元，例如未知数、方程、等量关系。
2. **标准题**：判断能否完成当前知识点的基本题型。
3. **读题与条件提取题**：判断能否找出题目问什么、关键条件是什么。
4. **步骤拆解题**：判断学生卡在设未知数、列式、计算还是检查。
5. **变式迁移题**：先换数字，再换条件，再换表达方式。
6. **提示反应题**：观察打开第几层提示后能继续推进。

选择学科后，系统应立即生成一组“起点题组”。这组题不是固定题库，而是由该学科的测试模块调用“题目逻辑库”，根据知识簇、目标维度和学生画像生成。

### 5.1 题目逻辑库

能力测试也必须有逻辑库，并且要和后续练习出题逻辑库打通。这里先定义第一层：**题目产生逻辑**。它负责一类题如何从样题、变量、变式和步骤边界中生成出来；它暂时不负责判断某个学生应该拿到哪道题。

题目逻辑库保存的不是固定题目，而是：

- 知识点逻辑，例如总量与差值关系、单价数量总价关系、文字转方程。
- 每个题型的样题 / seed question，用来定义这一类题的基本结构。
- 变量结构，例如总数、差值、未知数、单价、数量、总价。
- 变量变化边界，例如数字范围、整数 / 分数限制、答案是否必须整洁、条件之间的合法关系。边界首先用于保证题目有解、结果合理、不违反样题的基本逻辑。
- 能力维度映射，例如这类题可以测读题、列式、计算、迁移、提示依赖。
- 变式规则与边界，例如原题重做、换 1 个数字、换 2 个数字、换条件、改变问法、改变场景。
- 步骤延展边界，例如最多增加 1-2 个中间步骤、单位转换、额外条件提取、括号或合并同类项。
- 评分证据，例如对错、耗时、修改次数、提示层级、卡住步骤。
- 出题模式，例如初始探测、每日训练、阶段测试、专项复测。

这样设计的意义是：

- 早期可以用题库验证产品闭环。
- 中期可以用逻辑库生成大量可控变式。
- 后期算力允许时，可以接入实时 AI 出题，不再依赖传统题库。
- 即使题面实时生成，底层知识逻辑、能力维度和评分证据仍然稳定。
- 边界清楚以后，生成器先做合法性校验：不能出现无解题、矛盾题、答案不符合教学目的的题。
- 机器学习以后不是在无限空间里乱试，而是在样题、变量边界、变式边界和步骤延展边界内生成题目、校验答案、控制难度。

题目产生逻辑和用户匹配逻辑要分开：

- 题目产生逻辑回答：这一类题可以怎样生成？数字怎么变？条件怎么变？最多增加几步？答案如何校验？
- 用户匹配逻辑回答：这个学生今天需要哪类题？原题、轻变式还是加步骤题？比例和顺序是什么？

下一步再解决第二层方法论：题目逻辑库如何接入用户行为模式。系统不能只按知识点出题，还要根据学生昨天做对、做错、是否提示依赖、是否瞎答、是否过快、是否长题干耗时过高等行为，决定下一次出题比例和顺序。

第一阶段先采用可解释规则，例如：

- 抽取一定比例昨天做对的题，确认学生是否能复现。
- 对昨天做错的题进行原题重做和轻变式巩固。
- 对靠提示完成的题，检查无提示能否完成。
- 对瞎答型学生减少新题，增加读题确认。
- 对慢但准的学生减少机械重复，增加轻变式。

未来数据足够后，再用机器学习优化比例、排序和触发时机。

以数学一次方程应用题为例：

| 题目层级 | 示例题 | 背后观察 |
| --- | --- | --- |
| 基础概念 | 小明买 3 支相同的笔，一共 18 元。每支多少钱？ | 是否理解基本数量关系和未知量 |
| 读题提取 | 甲数比乙数多 8，两个数一共 38。题目最终要求什么？ | 是否先看问题，是否会区分目标和条件 |
| 标准列式 | 一个数的 3 倍加 5 等于 26。请列出方程。 | 是否能设 x，是否能把文字转成方程 |
| 变式迁移 | 改成“3 倍少 5 等于 25”，方程怎样变？ | 是否能从原题迁移到条件变化 |
| 提示反应 | 如果系统只提示“找等量关系”，你能继续吗？ | 需要几层提示，轻提示是否有效 |

每道题都必须绑定一个或多个能力维度，不能为了凑题而出题。系统记录的不只是对错，还包括答题时间、修改次数、提示层级、卡住位置和变式迁移情况。

测试不应该一次做得很长。第一版可以用短测试：10-15 题，20-30 分钟，先形成足够可用的初始能力图。后续再通过每日练习和阶段测试持续校正。

MVP 数学测试维度：

| 维度 | 测什么 | 示例判断 |
| --- | --- | --- |
| 基础概念 | 是否理解未知数和方程 | 知道可以设 x，但不稳定 |
| 读题能力 | 是否能先看题目问什么 | 容易先处理数字 |
| 条件提取 | 是否能找出关键条件 | 容易漏掉“比……多/少” |
| 等量关系 | 是否能把条件转成方程 | 总数 + 差值题不稳定 |
| 计算稳定性 | 方程求解是否稳定 | 计算基本稳定 |
| 变式迁移 | 换数字/条件/表达后是否还能做 | 换条件后正确率下降 |
| 提示依赖 | 需要几层提示才能继续 | 通常 2 层提示可推进 |

输出不是一个分数，而是多维能力图。

后续学习过程中的阶段测试也应使用同一个测试模块，只是测试目的不同：

```text
初始测试
-> 生成静态起点和静态学习曲线

阶段测试 / 动态测试
-> 校准当前水平
-> 调整动态学习曲线
-> 重新分解后续每日任务
```

## 6. 第五步：多维能力图

多维能力图是初始画像的核心组成部分，但不是初始画像的全部。

它应该展示：

- 当前综合起点
- 各能力维度强弱
- 明显强项
- 明显弱项
- 需要观察的风险点
- 最适合的第一阶段补弱方向

学生端不一定直接看到完整能力图。学生可以看到温和版本：

- 我现在在哪
- 我今天先练什么
- 我哪里已经不错
- 我下一步怎么做

家长 / 老师 / 系统后台可以看到更完整版本。

---

## 7. 第六步：目标确定

能力图回答“现在在哪里”，目标回答“要去哪里”。

学习目标由学生确认；已关联家长可以一起查看和讨论。系统提供建议，但不能替学生单方面决定。

目标可以有不同表达方式：

- 学段目标：达到小学六年级数学某知识簇的稳定掌握水平。
- 英语水平目标：达到某年级英语阅读 / 词汇 / 写作水平。
- 考试目标：托福、校内考试或阶段测评目标分数。
- 能力目标：能独立完成某类题型、阅读某类文章、完成某类表达任务。

目标确定后，系统要把“当前测试结果”和“目标水平”放在同一把尺子上，计算出差距。

这里的“目标水平”不能只是前端显示的一个标签。后台必须有一个明确的 `level_definition`，定义什么叫达到某一个水平。比如“达到小学六年级数学水平”，需要绑定：

- 对应学制 / 课程标准
- 需要覆盖的知识图鉴节点
- 必须稳定掌握的前置知识
- 对应题目的水平、难度、知识点、能力维度和变式深度标签
- 达标阈值，例如核心节点 80%+、关键前置 75%+、阶段测试确认、原题 / 变式 / 延展步骤都能独立完成
- 证据来源和时间窗口，尤其是阶段测试 / 校准测试，而不是只靠日常练习刷题

所以正确率是重要参数，但不能单独定义水平。系统应该综合：

```text
正确率
+ 题目水平标签
+ 知识点覆盖
+ 变式迁移
+ 是否依赖提示
+ 答题时间是否合理
+ 阶段测试确认
```

详细规则见 `docs/level-definition-framework.md`。

每日学习时间、每周学习频率和总学习周期不放在基本信息阶段，而是在初始测试完成、学习目标确定之后录入。它们不是学生的静态生理信息，而是生成静态学习曲线时使用的时间约束参数。

需要确认：

- 学习目标
- 目标水平
- 总学习周期
- 每日学习时间
- 每周学习频率
- 阶段测试节点
- 目标优先级

MVP 示例：

```text
目标：6 周掌握一次方程应用题
每日学习时间：30 分钟
每周学习频率：5 天
阶段测试：第 2、4、6 周
优先级：先稳读题和列式，再提高变式迁移
```

## 8. 第七步：生成静态学习曲线

静态学习曲线来自：

```text
初始画像
+ 多维能力图
+ 学习目标
+ 总学习周期
+ 每日学习时间
+ 每周学习频率
+ 统计基准
+ 可选生日文化模型
```

静态学习曲线要表达：

- 当前起点
- 目标终点
- 目标达成进度
- 内部离目标差距
- 每周预计水平
- 阶段测试节点
- 每日任务强度
- 第一阶段补弱重点

更准确地说，系统内部用“离目标的差距”计算，用户界面用“目标达成进度”展示。因为向上的曲线更符合用户直觉和心理感受。

```text
横轴：学习时间
内部计算：Gap to Target = 目标水平 - 当前能力水平，最终 Gap -> 0
外部展示：Progress toward Target = 1 - Gap to Target，最终 Progress -> 100%
```

系统根据以下因素计算这条静态曲线：

- 当前能力图
- 学生 / 家长共同选择的目标
- 总学习时长
- 每日学习时间
- 每周学习频率
- 同年龄 / 同年级 / 同目标学生的统计数据
- 学科和知识点自身难度

如果系统判断当前时间参数无法支持目标，应给出两种建议：延长总学习周期，或提高每日 / 每周学习强度。系统不应该默默生成一条不现实的曲线。

这条曲线不是最终判断，而是第一版计划。进入学习后，系统要根据真实反馈动态调整。

展示时应同时支持两条曲线：

- **静态曲线**：根据初始测试、目标、学习时间和统计数据生成的预期路径。
- **动态曲线**：由阶段测试、动态校准测试或专项复测发起更新的实际水平路径。

动态曲线可能低于静态曲线，也可能贴近静态曲线，甚至超过静态曲线。用两条向上的曲线叠加展示，家长、老师和学生都能直观看到：当前学习是在落后计划、符合计划，还是超过计划。

动态曲线不能被每日练习直接改变。每日练习数据会影响下一次出题逻辑，例如题目难度、变式层级、提示策略和错题重做顺序；但学生的阶段水平必须通过隔一段时间的测试来确认。这样可以避免某一天状态好或状态差，导致系统过早改变整体学习曲线。

```text
每日练习 -> 调整下一次出题逻辑
阶段测试 / 校准测试 -> 更新动态曲线
```

每日练习里的所有题都会进入下一次出题逻辑。这里包括必做题、做对题、做错题、提示后做对题、错题重做、同类型加练和“再练几道”。第二天出题不能只看错题，而要看完整历史：哪些题需要原题重做，哪些做对题需要抽查复现，哪些题已经可以减少重复，哪些题可以推进到轻变式或更高层级。

默认每日给题比例先定为：

```text
40% 昨天错题 / 未掌握题
25% 昨天做对题的抽查复现
25% 今天计划推进的新题
10% 挑战题 / 拓展题
```

这个比例是默认配方，不是固定规则。对了就是对了；系统不在学生端把做对题说成“不稳定”。后台只是抽样确认学生是否能复现。如果某个学生对做对题的复现率非常高，系统可以阶段性降低这 25% 的抽查比例，把更多题量分配给新题或挑战题。

阶段测试的作用是确认一段时间后的真实水平，并把这个水平写入动态曲线。测试频率可以按学科和目标确定，例如每 1-2 周一次，或在系统发现连续超前 / 连续落后时触发专项复测。

测试节奏应该有“建议测试”和“必须测试”两层：

- 连续练习一小段时间后，例如 3 天，系统可以建议做一次小测。学生可以选择接受测试，也可以跳过。
- 如果经过更长一段时间，例如 7-10 天，系统应要求完成一次阶段测试或校准测试。否则动态曲线不能继续可靠更新。
- 建议测试和必须测试的 interval 由系统提供默认值；已关联家长或老师可以在观察端配置。
- 学生跳过建议测试时，系统继续用每日练习数据调整下一次出题逻辑，但不更新动态曲线。

如果动态曲线超过静态曲线，系统应给学生两个选择；已关联家长可以共同参与：

1. **继续原目标**
   - 目标不变。
   - 预计达成时间缩短。
   - 后续任务以巩固、复测和保持稳定为主。

2. **保持学习强度不变**
   - 每日学习时间和每周频率不变。
   - 预期可达到的水平提高。
   - 后续任务可以进入更高阶变式或下一知识簇。

系统不能擅自替用户改变目标，而是把“缩短时间”和“提高目标”两个方案呈现出来，让学生确认；已关联家长可以一起讨论和建议。

## 9. 第八步：分解到每日任务

每日任务必须从静态学习曲线拆出来，而不是随机生成。

拆解依据：

- 本周目标
- 今日学习时间
- 当前弱项
- 任务强度
- 是否需要复习
- 是否需要测试

MVP 第一天任务示例：

```text
今日重点：题意分析与列方程
预计时间：30 分钟
任务 1：错题回访
任务 2：原题练习
任务 3：换 1 个数字
任务 4：知识图鉴归纳
```

## 10. 页面原型建议

接下来应补一个“入学诊断”流程，可以先做成 4 个步骤：

1. **基本信息**
   - 生日、年龄、年级、作息、专注时长、阅读舒适度、设备

2. **学习风格**
   - 反馈偏好、挑战耐受、节奏偏好、信息密度偏好

3. **专业能力测试**
   - 先用数学一次方程应用题的模拟测试结果

4. **目标与静态曲线**
   - 展示多维能力图
   - 确认目标
   - 录入每日学习时间、每周学习频率和总学习周期
   - 生成静态学习曲线
   - 点击进入每日任务

第一版可以先不做完整答题测试，而是用模拟测试结果展示流程。重点是把“先了解，再派任务”的产品顺序做出来。
